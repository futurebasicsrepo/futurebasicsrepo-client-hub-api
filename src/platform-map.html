One request, start to finish

  1. Cloudflare Access on work.thefuturebasics.com: staff sign in with Google Workspace before the console loads. A staff session that did not come through it is refused.
  2. Sign-in check: a signed JWT (7 days) is verified, then the person's standing: signed out everywhere, taken off their room's team, moved to another room.
  3. Access: staff are held to the modules ticked for them on Team access; a client's queries are scoped to their own room.
  4. Lab door: pages and engine code under /lab need a 12-hour HttpOnly Lab cookie from /v1/lab/door.
  5. Copy watch: library pulls are counted per account per hour; clients far past normal are paused. Every download is logged with a reference, written into Lab files.
  6. On the way out: security headers (CSP, HSTS, no framing), private caching for the Lab, noindex everywhere but the public pages, gzip.

Build, test, deploy

  • Code: plain ES modules, no build step. Pages are static HTML with their own scripts; the server renders nothing.
  • Schema: src/db.js creates and migrates tables at start-up, idempotently.
  • Dependencies: pinned by package-lock.json, installed with npm ci; npm run audit:deps checks advisories.
  • Tests: npm test (unit, incl. a check that every API route needs a sign-in or has a stated reason) and npm run journeys (end-to-end journeys against a real server, Postgres and headless Chromium/WebKit, with stand-ins for paid services).
  • Deploy: Railway builds the Dockerfile on merge to main; /health gates the rollout.
  • Watching it: Platform health in the work console checks every connection, job and setting without spending paid quota.
